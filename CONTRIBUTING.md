# Contributing to parentheses

parentheses is one person's project: I build and train it on a single laptop GPU in Bengaluru. Help is welcome, and the most useful help right now isn't code. This page says where to start, what I can and can't accept, and how to reach me.

Before anything else, read the [code of conduct](CODE_OF_CONDUCT.md). It covers how we treat each other, and it explains why the model is uncensored, which shapes what kinds of contributions fit.

## Ways to help

I said on Bluesky that I'd post specific areas for open contributions. Those aren't decided yet. Until they are, these are the open problems, roughly in order of how much they'd help.

### Licensed Dravidian text

This is the biggest one. From 2026-11-02, everything I release trains only on data whose licence allows commercial use, and most good Kannada, Tamil, Telugu and Malayalam corpora are non-commercial. If you know of, own, or can write text under CC0, CC BY, CC BY-SA, ODbL, Apache, MIT or similar, tell me. Text you wrote yourself and are willing to release under one of those licences counts too. The full rule is in [LICENSE_POLICY.md](LICENSE_POLICY.md), and [the roadmap](docs/ROADMAP.md#the-data-problem) explains why it matters.

Please don't send data under CC BY-NC, CC BY-ND, research-only or evaluation-only terms, data with no stated licence, or text generated by Llama models. I can't use any of it, however good it is.

### Checking the output as a native speaker

The automatic checks can tell whether an answer is in the right script. They can't tell whether it reads like a person wrote it. If you speak Kannada, Tamil, Telugu, Malayalam, Tulu, Koya, Kuvi or Kolami, run the model in your language ([setup guide](docs/SETUP.md)) and tell me what's wrong with it: grammar, odd word choices, things no speaker would say. Screenshots or copied transcripts are fine.

### Setup reports from other machines

I've only tested on Windows with an NVIDIA GPU. A report from Linux, macOS (including whether `--device mps` works), AMD GPUs or CPU-only machines is useful even when everything works.

### Bugs

Open an [issue on GitHub](https://github.com/uncoalesced/parentheses/issues). The reports I can act on include:

- the exact command you ran;
- your operating system, Python version and PyTorch version (`python -c "import torch; print(torch.__version__, torch.cuda.is_available())"`);
- your GPU, if any;
- the full output, including any warning lines from `chat.py`.

Check [the troubleshooting section](docs/SETUP.md#troubleshooting) first; the common problems are there. Security problems go through [SECURITY.md](SECURITY.md) instead of a public issue.

## Code contributions

Pull requests are welcome, but open an issue first for anything bigger than a small fix, so we can agree on the approach before you spend time on it. A few things about this codebase that will save you a review round:

- parentheses is a recurrent model (selective linear attention, the State Space Duality family), not a transformer. Changes to inference, export or evaluation have to work with the fixed recurrent state and `step()`, not a KV cache. [ARCHITECTURE.md](docs/ARCHITECTURE.md) explains the model; [DOCUMENTATION.md](docs/DOCUMENTATION.md) has the math and a map of the code.
- There's no big test framework. Each module carries assert-based self-tests on synthetic data. Run the ones in [DOCUMENTATION.md, section A.5](docs/DOCUMENTATION.md#a5-training-and-evaluation) before and after your change, and include their output in the pull request.
- `model/config.py` is the single source of truth for model settings. New `ModelConfig` fields go last and need a default, so older checkpoints still load.
- In `model/selective_linear_attention.py`, the chunked, dense and step paths must agree in float64. If you touch one, run that module's self-test.
- Don't add a dependency without asking in the issue first.
- Keep changes to training data scripts inside the licence rule above. A builder that pulls in a non-commercial source won't be merged.
- Run `python scripts/check_docs.py` if you rename anything. It fails when a doc still names code that's gone.

Anything that adds refusal behaviour, moralising, or a hidden content filter to the model won't be merged. The code of conduct explains why.

## Licences

By contributing, you agree that your contribution is released under the project's licences: the code under the licence the repository carries when it's merged (the [MIT License](LICENSE) today; [LICENSE_POLICY.md](LICENSE_POLICY.md) says releases from 1.0 onward move to Apache 2.0), and any training data you provide under the licence you state for it, which has to pass [LICENSE_POLICY.md](LICENSE_POLICY.md). The licence of the current model weights is in the [README](README.md#licenses).

## Contact

For anything that doesn't fit an issue, such as offering a dataset, asking whether a source's licence is usable, or wanting to help in a way not listed here, email **mail@uncoalesced.com**.
